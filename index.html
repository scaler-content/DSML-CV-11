    An animation studio wants a tool that suggests new character faces. A generative adversarial network (GAN) learns what faces look like by pitting a generator that forges images against a discriminator that inspects them. We build a small GAN in PyTorch, read its training curves, check it is not copying, break it on purpose, and see where GANs are used.

    01

    The problem: inventing new faces

    You work at an animation studio. Designing a character takes days: style, sketch, refine, color. The studio wants a tool that suggests new faces as a starting point.

    Task: from a pile of example faces, produce new ones that look like they belong but are not copies.

    • There are no labels. The model learns from the images alone.
    • An autoencoder is the obvious first try, but it is trained to rebuild the exact image it was given. Nothing in it pushes it to invent.
    • We want a model that learns what faces in general look like, then samples from that.

    Generative vs discriminative

    A discriminative model learns a boundary: which class is this point in? A generative model learns how the data is spread out, so it can produce new points that fit.

    Code: the two pictures
    
  
    An analogy: forger and inspector
    
  
    A forger prints fake banknotes. The first ones are awful and the inspector catches them all. But each rejection shows the forger what gave the fake away, so the next batch is better. Soon a few fakes slip through, so the inspector has to learn from those misses, and then the forger has to improve again. Round after round, both get better.
    
  
    That is a GAN. The forger is the generator; the inspector is the discriminator. Neither is told what a perfect note looks like: each only reacts to the other.
    
  
    random noise z → Generator → fake image ─┐
    real image from the dataset ───────────────┴→ Discriminator → real or fake?
    
  
      
    
    • The generator (G) turns a random vector into an image. It never sees a real image; it learns only from how D reacts.
      • 
    
    • The discriminator (D) scores an image for “this is real”.
      • 
    
    • They train in turns. A better D forces G to make better fakes; a better G forces D to look harder.
      •

    Setup and the face dataset
    
  
    All the knobs sit in one cell: seed 42, 5,000 faces, batch size 64, 30 epochs and a noise vector of length 128.
    
  
    The faces are drawn by code: each 64 × 64 anime-style face is built from random hair, eyes, skin tone and extras, and the seed makes it repeatable. The array has shape (5000, 64, 64, 3), dtype uint8, pixel range 16 to 255.
    
  
    
  
    Before training we put the channels first (PyTorch expects batch, channels, height, width) and rescale pixels from 0..255 to −1..1. A batch has shape (64, 3, 64, 64); the lecture’s sample batch ranges from −0.85 to 1.00. The reason for −1..1 comes up with the generator.

  03
  
    The discriminator
    
  
    An ordinary CNN classifier. Four stride-2 convolutions shrink the image (64 → 32 → 16 → 8 → 4) while adding channels, and a linear layer gives one number per image.
    
  
    LeakyReLU
    
  
    ReLU sends every negative input to zero, with zero slope there. LeakyReLU lets a fraction through (0.2 here), so the slope is never zero. This matters because G learns only from gradients that pass back through D: if D blocks them, G learns nothing.
    
  
    
  
    
  
    Code: activation and gradient plots
    
  
    
  
    Logit output and spectral normalization
    
  
    The output is a raw score (a logit). We leave the sigmoid out of the network and let the loss apply it, which is more numerically stable.
    
  
    Spectral normalization is an optional stabilizer: it rescales each layer’s weights so D cannot change its score too sharply between similar images. It is on by default, and we turn it off later to see what changes. Weights start from a normal distribution with standard deviation 0.02.

  04
  
    The generator
    
  
    It does the reverse: 128 random numbers in, a 64 × 64 × 3 image out. The tool is the transposed convolution: a stride-2 convolution halves the size; a stride-2 transposed convolution doubles it.
    
  
    output size = (input − 1) · stride − 2 · padding + kernel
    
  
      
    
    • One stride-1 transposed convolution makes a 4 × 4 map from the noise.
      • 
    
    • Four stride-2 transposed convolutions grow it 4 → 8 → 16 → 32 → 64, with a 3 × 3 convolution at 32 × 32 to smooth the picture.
      • 
    
    • BatchNorm and ReLU after each hidden layer.
      • 
    
    • tanh at the end keeps every pixel in −1..1. That is why we rescaled the real images: fakes live in −1..1, so real images must too, otherwise D could separate them by range alone.

  05
  
    How GAN training works
    
  
    
  
    Discriminator step. Real faces get label 1, generated faces label 0, using binary cross entropy with the two terms added: d_loss = BCE(D(real), 1) + BCE(D(G(z)), 0). The fakes are .detach()ed so the gradient stops at D and does not reach G.
    
  
    Generator step. Make fresh fakes, pass them through D, and label them 1. D’s weights are frozen for this step, but the gradient still flows through D into G: g_loss = BCE(D(G(z)), 1). So D wants D(G(z)) near 0, and G wants it near 1.
    
  
    Why label the fakes as real?
    
  
    The original paper writes G’s goal as minimize log(1 − D(G(z))). Early on, D rejects the fakes confidently, so D(G(z)) is near 0 and that function is almost flat: G barely learns when it needs to learn most. Flipping to maximize log D(G(z)) wants the same thing but has a strong gradient exactly there. This is the non-saturating loss, and labeling fakes as 1 is how you get it. The sentence “G wants D(G(z)) close to 0” is therefore wrong: D(G(z)) is D’s score for “real”, so G wants it near 1.
    
  
    
  
    Code: the gradient comparison
    
  
    
  
    The min-max game from the original paper:
    min over G, max over D of E[log D(x)] + E[log(1 − D(G(z)))]
    
  
    Two details from the DCGAN paper: Adam with lr 0.0002 and β1 = 0.5 (the usual β1 is 0.9, but the authors found that made training oscillate; β2 stays at 0.999), and weights starting from a normal distribution with std 0.02.
    
  
    
  
    Helpers and the diversity score
    
  
    The diversity score is the average distance between pairs of images. It lets us measure whether G makes varied faces or keeps repeating itself, with real faces as the reference: 50.1 for 32 real faces.
    
  
    The training function is the loop above plus bookkeeping: it reuses the same 32 noise vectors after every epoch so we can watch the same faces improve, and keeps snapshots from four moments in training. Defaults: 30 epochs on 5,000 faces.

    Reading the curves and the faces
    
  
    Both losses bounce around: that is normal for a GAN. In the main run D’s loss went from 0.818 to 0.777 and G’s from 1.979 to 1.863, while diversity rose from 13.8 to 46.1, close to the real faces’ 50.1.
    
  
      
    
    • Both losses noisy and in the same range, diversity rising: healthy.
      • 
    
    • d_loss near 0 and g_loss climbing: D is winning and G gets no useful signal.
      • 
    
    • Diversity stuck well below real: G is repeating a few faces.

    New faces, and are they copies?
    
  
    Fresh noise gives new faces (diversity 45.5 against 50.1 for real faces). For each generated face we find the closest training face by pixel distance and show them together: identical pairs would mean memorization; related but different pairs mean it learned the style.
    
  
    
  
    Walking through latent space
    
  
    Take two noise vectors and blend between them in ten steps. If G learned something real, the faces change smoothly (hair color slides, eyes shift); if it only memorized, you would see sudden jumps.

  07
  
    Why GANs are hard to train
    
  
    Two networks pulling against each other can fail in ways a normal classifier never does.
    
  
    
    
    1
    Vanishing gradients
    If D gets too good too fast, its score for fakes sits at 0 and G gets almost no gradient. The non-saturating loss and spectral normalization both help.
    
    
    2
    Mode collapse
    The data has many kinds of faces (modes). G finds a few that fool D and keeps producing only those. Each image looks fine, but they all look alike. The basic loss does not punish this, which is why we track diversity. Watching samples is the first defense.
    
    
    3
    No single quality number
    Loss does not measure picture quality. You monitor samples, and for serious work use a metric such as FID.
    
  
    
  
    
  
    Break the GAN: no spectral normalization
    
  
    The same training with spectral normalization off, for the same 30 epochs. Compare the final epoch (the lecture’s own summary):
    
  
    D lossG lossDiversity (of real)
    With spectral norm0.781.860.92
    Without spectral norm0.405.580.80
    
  
    Without it, D’s loss stayed low while G’s loss sat well above 1: D was winning most rounds, and the diversity score ended lower. In a scaled-down test the lecture saw D near 0.1 to 0.2, G around 6 and diversity at roughly half; exact numbers differ with seed and hardware.

  08
  
    Where GANs are used
    
  
    
  
    For text-to-image work, diffusion models have largely replaced GANs: they are easier to train and cover more variety. GANs still win on speed, since one forward pass makes an image.
    
  
    Key takeaways
    
  
      
    
    • A discriminative model learns a boundary; a generative model learns how the data is spread out so it can sample new data.
      • 
    
    • In a GAN the generator turns noise into images and the discriminator scores images as real or generated; they train in turns, and G learns only through D’s gradients.
      • 
    
    • Generators use transposed convolutions and end in tanh, so real images are rescaled to −1..1; discriminators use LeakyReLU to keep gradients flowing.
      • 
    
    • Labeling fakes as real (the non-saturating loss) has the same goal as the original loss but strong gradients when D rejects fakes confidently.
      • 
    
    • Loss does not measure picture quality: track diversity, look at samples, and use nearest-neighbor checks and latent walks.
      • 
    
    • Common failures are vanishing gradients and mode collapse; spectral normalization is one stabilizer.
